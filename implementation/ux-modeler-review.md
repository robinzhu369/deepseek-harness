# 建模人员体验与交互改造记录

## 实际体验

2026-09-16，通过浏览器实操现有工作台。使用用户指定的 fraud_transaction_data.csv（700 行、38 列）；模型测试改用用户指定的本机 qwen3.5:9b。原始交易记录不写入此报告，不发送公网。

| 观察到的卡点 | 用户影响 | 改造决定 |
|---|---|---|
| 首屏是长表单，数据集为空却没有上传入口 | 不知道第一步是什么 | 首屏直接给出上传入口和三步引导 |
| 数据中心需要“选择文件、上传、手填 JSON、提交导入” | 普通建模人员要理解接口格式 | 一次“上传并解析”，基础选项可视化，JSON 收入高级设置 |
| 更换文件后旧上传 ID 与进度仍保留 | 容易误续传或导入上一份文件 | 文件变化立即清空关联上传状态 |
| 导入显示 importing，没有下一步和失败原因 | 用户只能反复刷新 | 自动刷新并展示准备中、完成、失败及下一步 |
| 新建任务先要求 Skill ID、拟合范围、业务任务复选框 | 实现细节抢占主流程 | 默认创建业务任务，选填功能折叠，已发布 Skill 用选项选择 |
| 右侧未运行就显示 Run 选择和空白 | 缺少操作指导 | 任务路线和下一步提示；已有执行后才显示历史控制 |
| 对话暴露事件编号与类型，工具输出占据主视图 | 难以阅读分析结论 | 用户/助手内容突出，工具与技术细节折叠 |
| 页面大量等权重按钮和重复刷新 | 难以找到主要操作 | 每个阶段保留一个明确主按钮，低频管理降级 |

## 布局设计

保留官方 Harness 三列扩展：左侧约 240px 放新建任务、数据/技能/模板和任务历史；中间为主要工作区，空态引导上传和描述目标，任务中显示对话与确认卡，输入区固定在底部；右侧约 320px 显示下一步、阶段进度和正式产物，画布作为次级页签。响应式与滚动由既有布局所有者管理。

流程：选择项目 → 上传并解析 → 选择已准备好的数据 → 描述目标并创建任务 → 本地模型分析 → 审批处理方案 → 查看执行与下载产物。审批、字段角色保护和 Skill 发布条件保持服务端强制校验。

## 执行顺序

先修改前端布局、文案、可视化导入和状态衔接；再根据实测补充后端导入失败信息与会话开始/恢复行为。完成后以同一交易数据复查实际流程并记录验证结果。

## 本地模型实测结果

Ollama 端点为 `http://127.0.0.1:11434/v1`，复用已安装的 `qwen3.5:9b`。首次实测实际上下文仅 4096 token，长报告之后模型偏离原任务。随后使用本地别名 `qwen3.5:9b-harness`，实际运行上下文为 32768 token；权重没有重新下载或覆盖。相关配置位于 `deploy/data-agent/ollama/`。

浏览器实际完成：上传 173819 字节 CSV → 明确 `fraud` 标签与 `policy_id` 标识 → Worker 解析成功 → 从就绪数据创建任务 → Qwen 调用诊断工具 → Worker 发布报告 → 页面读取字段统计 → Qwen 读取报告并生成中文建议。整个链路使用回环服务，未调用公网模型。原数据未修改，未批准任何清洗建议。

| 核对项 | 已发布报告 | Qwen 中文总结 | 判定 |
|---|---:|---:|---|
| 行数 / 列数 | 700 / 38 | 700 / 38 | 一致 |
| 精确重复行 | 0 | 0 | 一致 |
| fraud=0 / fraud=1 | 519 / 181 | 519 / 181 | 一致 |
| collision_type 的问号数 | 123 | 123 | 一致 |
| property_damage 的问号数 | 259 | 159 | 错误 |
| police_report_available 的问号数 | 247 | 37 | 错误 |
| insured_relationship 不同值数 | 6 | 约 9 | 错误 |

模型还提出了缺乏报告依据的 age 问号与中位数处理建议。结论是“本地集成可用，当前 9B 输出未通过业务质量核对”，不能将连通性或工具执行成功表述为 Skill 质量验收通过。报告卡直接展示已发布行列统计、空值、不同值及已观测问号数，供人工核对；问号未出现在报告 top 列表时显示破折号，不推断为零。

## 实测驱动的后端修正

- 导入列表返回 Worker 失败分类，避免只显示失败状态。
- 消息接口新增 `wait_for_idle: false`，立即返回 HTTP 202；会话仍由既有 Harness 执行，历史持续提供状态与结果，忙碌期间拒绝第二条消息。默认同步接口继续兼容既有消费者。
- 手工测试 Worker 原先仅服务本地测试项目，已将用户已有的反欺诈项目加入该测试账号的明确项目范围。

## 验证边界

这是建模准备体验与本地模型集成测试，不是模型训练、真实业务指标验收或 Skill 正式发布。Parquet、无表头 CSV 与精确类型转换仍通过高级设置配置；已有会话保留冻结模型配置，切换模型后需创建新任务。

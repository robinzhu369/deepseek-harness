# T12 工作台使用与验证

## 已交付

工作台是 Harness 的可选 React 插件，通过现有 Web profile、根布局和认证连接加载；默认 Web 配置不启用它。

- 左列：项目与会话创建、搜索、重命名、切换；数据中心、Skill 管理、模板入口。
- 中列：实际 Harness 消息、工具结果、Markdown 与回合错误；统一提案、证据、摘要绑定的审批、拒绝及运行提交。
- 右列：Run 选择、冻结版本、实际节点状态/处理量、暂停/取消/业务分支/重跑与产物；切换到 React Flow 画布进行节点、参数、引用和连线编辑。
- 草稿、流程版本与可复用模板；历史 Run 只读，复制生成独立草稿；保存与重新提案不会沿用旧审批。
- Skill 阶段入口显示版本与最近评测，选定版本后创建新的规划会话；候选/停用版本继续受服务端发布门禁限制。
- 管理弹窗关闭后恢复原会话、Run 与草稿；拖动分隔线后可保存列宽，刷新后恢复。凭证只在内存中，刷新须重新登录。

## 启动

1. 按编号应用尚未执行的数据库迁移，直到 `008_workbench.sql`。
2. 配置 `DATA_AGENT_HOST_CONFIG`：沿用部署示例的完整 JSON，并启用其中的 `harness` 配置。数据库、对象存储目录、用户凭据摘要、模型路由和环境摘要必须使用当前部署的真实值。
3. 将 `DATA_AGENT_DOMAIN_ENDPOINT` 设置为上述监听器的精确回环源，例如 `http://127.0.0.1:55440`。浏览器上传缓冲上限默认 64 MiB，领域服务仍独立执行自己的限制。
4. 从仓库根目录构建并启动：

```sh
pnpm run build:lib
pnpm dsh --profile web --patch deploy/data-agent/workbench.source.patch.yml
```

打开 dsh 输出的带认证信息的本机地址，再输入领域用户凭证。Worker 仍按现有部署方式独立运行；浏览器和 Host 不承担数据计算。正式数据接入应通过已配置的内网 HTTPS 入口；文件摘要计算要求浏览器安全上下文（HTTPS 或 localhost）。

## 操作要点

- 创建会话时绑定数据集、用途和 Skill 版本。修改 Skill 版本使用新的规划会话，旧运行保留原快照。
- 画布保存版本后，填写目标与证据 JSON，生成提案。变更型算子缺少有效证据会被服务端拒绝；未知影响不会显示为已测结果。
- 审批绑定完整提案摘要和允许移除比例。候选产物仍需检查实际影响并作二次决定。
- “停止回复”只停止模型；取消 Run 或业务任务使用对应按钮，直到后端确认才显示已取消。
- 选择历史 Run 后，后续新 Run 不抢占选择。点击“返回保留的草稿”继续编辑。
- 重跑从已有业务任务入口选择范围、前序/来源与复用意图，生成新的 Run。对话提案与画布提案共用后端版本和审批系统。

## 验证范围与限制

真实浏览器回归加载完整 dsh Web 组合及 PostgreSQL，仅将外部模型替换为确定性适配器。验证覆盖消息→领域工具→Run、三列几何、历史只读、草稿保存、模板、审批提交防重、历史选择保持、拖动/保存列宽、断网提示和重新登录恢复。固定预期见扩展测试目录的 `workbench.expected.txt`。

界面使用轮询与持久化快照，导航最多读取 200 个 Run/提案；对话显示最近 200 条已读取事件。复杂算子参数、证据和 Skill 包当前采用 JSON 表单，浏览器上传先在配置限制内缓冲并计算摘要。冷会话须显式恢复；完整业务模型评测、百万行全链路、内网离线交付与产品 AC 验收分别保留在 T13–T16，不因本地界面测试通过而自动通过。

四个 Skill 0.1.1 候选的完整业务质量评测仍未完成，严格发布门禁保持不通过。本节点没有调用公网模型，也没有改变其发布状态。

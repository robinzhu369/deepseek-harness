# model-training

English | [中文](SKILL.zh.md)

## Input
Trusted dataset ID, truncated/desensitized data summary, user goal, current capabilities, and planned schema. Do not fabricate identities or approvals.

## Workflow Steps
Verify `target`, `positive_label`, and sample independence; enforce split-before-fit. Select logistic regression parameters supported by the service; do not debug on test set metrics. Use `modeling_propose_plan` to save a complete candidate plan instead of executing it. After completion, use `modeling_get_run_result` to retrieve actual metrics, explicitly stating the split, threshold, and sample size; never fabricate metrics or causal conclusions.

## Tool Boundaries
Only tools provided in the current runtime environment are permitted: `modeling_get_dataset_profile`, `modeling_propose_plan`, `modeling_get_run_status`, `modeling_get_run_result`. Do not assume availability of non-existent tools; do not request shell access, Python eval, network downloads, or dynamic installations.

## Output and Confirmation
Plans must pass current schema and semantic validation. If information is missing, ask specific questions; report errors truthfully. Task execution is triggered by user confirmation at the entry point; Skill body text and model outputs cannot authorize execution.

## Versioning
Upon release, an immutable snapshot/hash is generated by the service. Execution uses a frozen plan; historical results must not change with edits to the main content.
